```text

```

and the first missing equation as a successor-equivariance square at the first `B`.

That is the wrong first gap under the ratified architecture.

The package inserts this dependency chain:

```text

```

The active authority requires:


No source in `p5_v8u` proves that a successor on `Z/12Z` generates `P_t` or must exist before `P_t`. The package therefore promotes one possible downstream coordinate presentation into an upstream generative dependency.

## Exact findings

The package contains no dedicated derivation for:

The finite address map and cyclic successor may become useful after a pairing-first retained object has been built and a finite coordinate surface is chosen.

### F3. The spectral-module requirement is asserted too early

`p5_v8u` states:

```text
AMBIENT_SPECTRAL_MODULE_ROLE:
REQUIRED_FOR_EIGENBASIS_AND_PAIRING_FORMALIZATION
```

The clean law does not yet identify `P_t` as a spectral eigenform, bilinear form, sesquilinear form, quadratic refinement, or operator-valued pairing.

A spectral module may be needed for one later realization. It is not licensed as an upstream requirement before the primary pairing type is determined.

Correct status:

```text

POSSIBLE DOWNSTREAM FORMALIZATION
NOT AN ESTABLISHED PREDECESSOR OF P_t
```

### F7. The abstract cycle results remain true but are not Orthad progress

The conjugacy and translation-generator calculations on `Z/12Z` are valid finite group results.

They establish coordinate nonuniqueness after choosing a 12-point cyclic surface. They do not establish any part of the primary pairing recurrence.

### F8. Direct pytest execution is not self-contained

The package verifier injects `src/` into `sys.path` and reports twelve passing tests. Running `pytest` directly from the package root fails during collection because `orthad_v8u` is not importable without that path injection.

This is a packaging defect, not a mathematical defect. The next package should make the ordinary test command work or state the exact required environment.

### F9. The fresh ZIP verifier fails its own no-cache gate

Running the packaged verifier on the supplied ZIP reproduced:

```text
19/20 gates passed
NO_CACHE_BYTECODE: FAIL
```

The archive is cache-free before execution. The verifier imports package modules without disabling bytecode creation, then detects the `__pycache__` and `.pyc` files it created in the temporary extraction.

This is a verifier-design defect. The next package must run verification with bytecode disabled and test cache creation blocked.
